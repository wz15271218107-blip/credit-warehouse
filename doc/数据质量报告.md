## 二、分类校验明细

### 2.1 唯一性（主键不重复）

```sql
SELECT id, COUNT(*) AS cnt FROM dwd.loan_dwd
GROUP BY id HAVING cnt > 1;
```
**结果：0 行**——DWD 明细表无重复贷款 id，一笔贷款一行，粒度干净。

### 2.2 完整性（行数勾稽链）

```sql
SELECT 'src' AS layer, COUNT(*) AS rows_cnt FROM src.loan_raw
UNION ALL SELECT 'ods', COUNT(*) FROM ods.loan_ods
UNION ALL SELECT 'dwd', COUNT(*) FROM dwd.loan_dwd
UNION ALL SELECT 'fact', COUNT(*) FROM dwd.fact_loan;
```

| layer | rows_cnt | 说明 |
|---|---|---|
| src | 42542 | 原始 CSV 落库，原样 |
| ods | 42542 | 贴源层，与 src 一致（入仓未丢数） |
| dwd | 38979 | 清洗后明细（剔除进行中/状态空） |
| fact | 38979 | 事实表，与 dwd 一一对应 |

**剔除勾稽**：ods(42542) − dwd(38979) = **3563** = 进行中(3556) + 状态空(7)，与 Day 3 清洗记录一致。

### 2.3 空值率（外键完整性）

```sql
SELECT SUM(customer_key IS NULL), SUM(date_key IS NULL), SUM(region_key IS NULL)
FROM dwd.fact_loan;
```
**结果：0 / 0 / 0**——事实表的三个外键全部命中维度表，无 JOIN 丢失行。这是星型模型最关键的质量闸：一旦出现 NULL 外键，说明维表没兜住，报表 join 会漏数。

### 2.4 准确性（汇总 = 明细）

```sql
-- DWS 三表交叉勾稽
SELECT 'dws_customer', SUM(loan_cnt), SUM(default_cnt) FROM dws.dws_customer
UNION ALL SELECT 'dws_date', SUM(loan_cnt), SUM(default_cnt) FROM dws.dws_date
UNION ALL SELECT 'dws_region', SUM(loan_cnt), SUM(default_cnt) FROM dws.dws_region;
-- 三行均为 38979 / 6203

-- 明细金额基准
SELECT ROUND(SUM(loan_amnt),2) FROM dwd.fact_loan;
-- 417052675.00，与 ads_overview.total_amount 一致
```

三个主题（客户/月份/地区）切法不同，但总量必须相同——这是"先聚后算"口径自洽的证明。

## 三、差异说明（非错误，业务规则预期）

**ads_region_default 笔数和 = 38867，与明细 38979 差 112 笔。**

原因：ADS 表落地了 Day 7 口径决议——`WHERE loan_cnt >= 50` 展示层门槛，过滤掉样本量不足的小州：

| 州 | 笔数 | 违约率 | 过滤原因 |
|---|---|---|---|
| ME | 3 | 0% | 样本过小 |
| ID | 9 | — | 样本过小 |
| NE | 11 | 54.5% | 样本过小，违约率失真 |
| IA | 12 | — | 样本过小 |
| IN | 19 | — | 样本过小 |
| MS | 26 | — | 样本过小 |
| TN | 32 | — | 样本过小 |
| **合计** | **112** | | 与差值 112 完全吻合 |

**结论**：该差异为业务规则的预期代价，非数据质量问题。完整明细仍保留在 dws_region（50 行全量），ADS 仅做展示层过滤，可追溯、可恢复。

## 四、质量口径备忘

1. **计数勾稽优先于金额勾稽**：笔数对不上是硬错误（漏行/重行），金额对不上多半是小数位舍入。
2. **预期差异要留档**：门槛、过滤、去重造成的差异必须在报告中说明原因和数字，否则审计会误报。
3. **外键 NULL 是红线**：事实表外键一旦出现 NULL，必须立即回溯维表 join 逻辑，不带病上线。
4. **校验要可复跑**：本报告全部 SQL 归档在 `sql/day9_quality_check.sql`，每次数据重灌后可一键重跑验证。
