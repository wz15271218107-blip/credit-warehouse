## 五、踩坑记录（金矿）

### 坑 1：隐形双空格（2,694 行匹配失效）
- **现象**：DWD 行数 36,285 vs 预期 38,979，差 2,694
- **定位**：差异数恰好 = 'Does not meet...Fully Paid'(1,933) + '...Charged Off'(761) 的数量
- **根因**：CSV 源数据 'Does not meet the credit policy.  Status:xxx' 是**双空格**，IN 精确匹配失效
- **确认**：`LENGTH(loan_status)` 对比（51 vs 50，多 1 空格）
- **解决**：`REPLACE(loan_status,'  ',' ')` 标准化，SELECT/CASE/WHERE **三处一致**

### 坑 2：三处不一致（761 行标签打错）
- **现象**：中间版本 WHERE 用了 REPLACE 但 CASE 没同步，761 行 'Does not meet...Charged Off' 被标成 0
- **教训**：同一字段在同一条 SQL 多处使用，处理必须完全一致

### 坑 3：STR_TO_DATE 缺日返回 NULL（sql_mode 拒绝零日）
- **现象**：`STR_TO_DATE('Dec-2011','%b-%Y')` 返回 NULL
- **根因**：缺日时默认补 0（2011-12-00），MySQL 8.0 默认 sql_mode 含 `NO_ZERO_DATE` 拒绝零日期
- **解决**：`STR_TO_DATE(CONCAT(issue_d,'-01'),'%b-%Y-%d')` 显式给日

### 坑 4：带前导空格的利率（' 10.99%'）
- **现象**：int_rate 前有空格，直接 REPLACE 后 '/100' 仍可转换（隐式转换跳空格），但不规范
- **解决**：先 `TRIM()` 再 REPLACE + CAST

### 坑 5：空字符串 ≠ NULL（emp_title 2,625 行空串）
- **现象**：`emp_title IS NULL` 查出来 0 行，但实际 2,625 行空串
- **教训**：CSV 缺失常见的是**空字符串**而不是 NULL，两种都要处理

### 坑 6：项目自带工具坑
- Workbench 导入向导导 4 万行 CSV：1 小时只导 701 行 → 改 Python 批量导入（5,000 行/批）
