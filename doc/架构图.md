# 信贷违约数仓 · 架构图

## 一、分层架构总览

```
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│  src   │ → │  ODS   │ → │  DWD   │ → │  DWS   │ → │  ADS   │
│ 原始数据 │   │ 贴源层  │   │ 明细层  │   │ 汇总层  │   │ 应用层  │
└────────┘   └────────┘   └────────┘   └────────┘   └────────┘
 42,542×52    42,542×54   38,979×13    (第2周)      (第2周)
   原样存      加时间戳     清洗+建模     按主题汇总    给报表用
```

**一句话**：原始进 ODS、洗干净进 DWD、按主题汇总进 DWS、给报表进 ADS。

## 二、每层说明

### src（原始层）
CSV 数据原样落库，52 列全用 TEXT 宽松类型，不做任何加工。作用：留底，保证原始数据可追溯。

### ODS（贴源层）
- 结构 = raw + `dt`（数据日期）+ `etl_time`（入仓时间）两个时间戳
- 时间戳的意义：**数据属于哪天、何时入仓**，用于留底、追溯、按天增量
- 42,542 行与 raw 完全一致，不改业务含义

### DWD（明细层，第 1 周重点）
把 ODS 洗成"干净、可分析"的明细：
- **口径过滤**：只保留已终结贷款（剔除进行中 3,556 + 状态空 7 行），42,542 → 38,979
- **空行清理**：删除 id 为空的全空垃圾行
- **空格标准化**：双空格 `Does not meet the credit policy.  Status:xxx` → 单空格（REPLACE）
- **违约打标签**：`is_default` 0/1，口径 = Charged Off / Default / Does not meet...Charged Off（6,203 违约 / 32,776 正常）
- **日期格式化**：`Dec-2011` → `2011-12-01`（STR_TO_DATE + CONCAT 补日）
- **利率转数值**：`10.65%` → `0.1065`（TRIM + REPLACE + CAST）
- **缺失处理**：职位空 → `Unknown`；收入空 → `NULL`（不硬转 0）

### DWS / ADS（第 2 周目标）
- DWS：按客户/日期/地区主题轻度汇总
- ADS：直接给报表/大屏用的结果表

## 三、星型结构（Day 4）

```
                    ┌─ dim_customer（客户字典，38,979 行）
                    │    member_id / emp_title / annual_inc
                    │    home_ownership / emp_length
                    │
  fact_loan（事实表）─┤  一笔贷款一行（38,979 行）
   38,979 行         │   loan_id + 3 个外键
                    │   + loan_amnt / int_rate / installment
                    │   + term / is_default
                    │
                    ├─ dim_date（日期字典，55 行）
                    │    full_date / year / month / quarter
                    │
                    └─ dim_region（地区字典，50 行）
                         state_code
```

- **事实表**：只存"外键编号 + 数字指标"，一笔贷款一行（粒度）
- **维度表**：存"描述属性"（谁/何时/何地），一行一个对象
- **外键连接**：`fact.customer_key = dim_customer.customer_key`（日期/地区同理）
- **查询方式**：事实表 JOIN 维度表，缺啥拼啥

## 四、为什么这样设计

1. **层次分明、职责隔离**：每层只管一件事，改动互不干扰
2. **数据血缘清晰**：出问题能逐层定位（应用层数字不对 → 查 DWS → 查 DWD → 查 ODS）
3. **避免重复计算**：上层直接复用下层成果，不用每次重算明细
4. **星型结构查询快**：事实表居中直连维度表，JOIN 少、好理解

## 五、数据流示例（一笔贷款的旅程）

```
原始 CSV 一行         → src.loan_raw（原样）
加 dt/etl_time       → ods.loan_ods
清洗+标违约          → dwd.loan_dwd（is_default=0/1）
拆成外键+指标        → fact_loan + dim_customer + dim_date + dim_region
按州看违约率        → fact JOIN dim_region GROUP BY state_code
```
